## Status in Phase 1

The CLI accepts a `--disable-analytics` flag and an `analyticsDisabled` context flag today, but no telemetry sender is wired up yet — the flags are stubs reserved for a later phase. Nothing is transmitted when you run the CLI in Phase 1.

## Planned telemetry

When CLI telemetry ships, it will follow this contract:

- One anonymous event on successful project creation with selected options (language, framework, orm, migrations, database, packageManager, addons, git, install), `cli_version`, `node_version`, `platform`, and how the CLI was driven
- No project names, paths, file contents, secrets, IPs, or persistent identifiers
- Honoring `--disable-analytics` and the cross-tool [`DO_NOT_TRACK=1`](https://consoledontonottrack.com) convention

## Disable telemetry

Once enabled, telemetry can be disabled for a single run:

```bash
uvx tristack my-api --disable-analytics
```

or permanently by exporting `DO_NOT_TRACK=1` in your shell profile.

## Full transparency

One project event per successful scaffold; no project identifiers. If in doubt, pass `--disable-analytics` — you can still use every CLI feature.
