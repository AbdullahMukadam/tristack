# TriStack — Journal

Append-only log of gotchas and learnings worth keeping (debugging discoveries, decisions that surprised us, framing for future work). Add a dated bullet when something non-obvious is learned; keep each entry short and specific. Do not link this file from `AGENTS.md` — it is a working log, not an entry point.

Format:
`- YYYY-MM-DD — <area>: <what happened / what we learned>.`

## Entries

- 2026-09-28 — **CLI / pip on Windows**: a standalone `pip` is often NOT on PATH on Windows even when Python is installed. The CLI hardcoded `pip` as the bin, so `pip install -e .` failed with `'pip' is not recognized`. Fix: new `apps/cli/src/utils/pip-command.ts` resolver (`resolvePipCommand`) prefers `pip`, then falls back to `python -m pip`; used by both `install-dependencies.ts` and `requirements.ts`. Note: `python -m pip --version` reports the launcher's Python version, so the baseline check now reads a real pip instead of a false "not found". A scaffold's `requires-python = ">=3.12"` still fails on Python 3.11 hosts (surfaced by pip itself), which is an environment mismatch, not a CLI bug.
- 2026-09-28 — **Templates / Tortoise ORM**: Tortoise 0.25+ moved to a context-scoped API. `Tortoise.init()` in a FastAPI lifespan no longer makes connections visible to request handlers (they run in separate tasks) → runtime error "No TortoiseContext is currently active." Fix: pass `_enable_global_fallback=True` to `Tortoise.init()` (same mechanism `RegisterTortoise` uses for FastAPI). Also: `fields.UUIDField(pk=True)` is deprecated in favor of `primary_key=True`.
- 2026-09-28 — **Templates / Python on Windows**: Python 3.14 on Windows ships no IANA tz database; `zoneinfo.ZoneInfo("UTC")` fails with "No time zone found with key UTC". Tortoise's `DatetimeField(auto_now_add=True)` hits exactly this. Fix: add `tzdata` as a dependency in generated projects. Cross-platform-safe on Linux/macOS too.
- 2026-09-28 — **Templates / schemas**: Pydantic v2 does not coerce a `UUID` object into a declared `id: str` field (lax mode still validates as `string_type` error). Shared schemas use `id: str`, so Tortoise (which returns `UUID`) must stringify at the repository layer: `ItemResponse(id=str(item.id), …)`. SQLModel is unaffected (its id is already a `str(uuid4())`).
- 2026-09-28 — **README generator**: procedural READMEs must be ORM/framework-aware about migrations — Tortoise/SQLModel/SQLAlchemy auto-create schemas on startup (no manual migration step), Alembic requires `revision --autogenerate` before `upgrade head`, and Django needs its own `manage.py migrate`. The run command also differs per framework: Django → `python manage.py runserver`, Litestar → `litestar run --reload`, Flask → `flask --app src.main run`, others → `uvicorn src.main:app`.
- 2026-09-28 — **Distribution / installers**: GitHub release assets on Windows are `tristack-windows-x64.exe.zip` (not `tristack-windows-x64.zip`); `install.ps1` must request the `.exe.zip` name. `install.sh` uses `${platform}.tar.gz` which matches the actual Linux/macOS asset names — no fix needed there.
- 2026-09-28 — **Web / Fumadocs code tabs**: the custom `CodeBlockTabs/*` components come from `fumadocs-ui/dist/mdx.js` (upstream default MDX components), not our source. Use stock Fumadocs `Tabs`/`Tab`; both render differently under our global.css overrides (we reverted the `#nd-notebook-layout` token/border-radius flattening so tabs keep upstream styling).
- 2026-09-28 — **Local testing**: run the built CLI from a scratch dir with a bare project name; absolute paths are rejected by project-name validation ("invalid characters"). Build `apps/cli/dist/cli.mjs` via `bun run build:cli` before testing. Root `package.json` script `"cli"` still references the stale `dist/cli.js` path.
- 2026-09-30 — **Boot verification / harness**: `execa` rejects with a non-zero `exitCode` instead of throwing only on signal death, so reading `result.exitCode` (not `result.failed`) is what makes install/prepare failures visible; before this, every case failed at install. Also: server stdout/stderr must be appended to the persisted failure log — asserting against `serverLog` inline loses it on the very failures you need it for.
- 2026-09-30 — **Templates / Alembic**: `script.py.mako` imported `sqlmodel` unconditionally, so Alembic autogenerate under the SQLAlchemy ORM died with `ModuleNotFoundError: No module named 'sqlmodel'`. Fix: guard the import with `{{#if (eq orm "sqlmodel")}}`.
- 2026-09-30 — **Templates / SQLAlchemy**: the declarative `Item` model declared `id = Column(String, primary_key=True)` with no default, so `POST /api/v1/items` failed with `NOT NULL constraint failed: items.id`. SQLModel and Tortoise both defaulted their ids. Fix: `default=lambda: str(uuid4())`.
- 2026-09-30 — **Templates / Flask**: the Flask route handlers are `async def`, but plain `flask` cannot run async views ("Install Flask with the 'async' extra"). Fix: depend on `flask[async]` (`{ extras = ["async"] }` in Poetry) in all three pyproject templates. Also added the missing `tzdata` dependency for Tortoise to `pyproject-poetry.toml.hbs` (the earlier Windows tz fix had only landed in the uv/pip variants).
- 2026-09-30 — **Templates / Litestar**: the whole framework scaffold was unbootable against Litestar 2.x, in five separate ways. (1) `litestar run` autodiscovers only `app`/`application` in `app.py`, and there was no root entrypoint — added a root `app.py` re-exporting `create_app`/`app`. (2) `Provide` is not importable from `litestar` (it lives in `litestar.di`), and using it as a parameter default is invalid (`unhashable type: 'Provide'`) — it belongs in the handler's `dependencies={...}`, and an async-generator provider needs `sync_to_thread=False`. (3) Route decorators passed `path` twice (`@get("/", path="/items")` → "got multiple values for argument 'path'"). (4) `lifespan=` expects a list of ASGI middleware, not an async context manager — use `on_startup=[...]`. (5) Exception handlers are invoked **without** `await`, so `async def` handlers return a coroutine and every request 500s with `'coroutine' object has no attribute 'to_asgi_response'`. Middleware: `PureMiddleware` never existed; `AbstractMiddleware` is deprecated since 2.15 and its custom `__init__` skipped the base `__init__` that sets `exclude_pattern` — use `ASGIMiddleware` with a `handle()` method and pass an **instance** (`middleware=[RequestLoggingMiddleware()]`), since `ASGIMiddleware.__call__(app)` _returns_ the ASGI callable.
- 2026-09-30 — **Boot verification / debugging**: patching the already-scaffolded project in a temp dir and re-running the server directly is far cheaper than a full regenerate-and-rebuild cycle per fix; the matrix run is the last mile, not the inner loop. Watch out for `uv` runs interrupted mid-sync — the venv is left without `typing_extensions` (a real Litestar dependency), which surfaces as a confusing in-package import error rather than a missing dependency.
