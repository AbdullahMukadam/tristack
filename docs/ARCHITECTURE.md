# TriStack — Architecture

This document gives a high-level architectural overview. For template-authoring details, canonical layouts, and layering rules see `docs/template-architecture.md`; for records of specific decisions see `docs/adr/`.

## 1. Monorepo topology

Bun + Turborepo monorepo, ESM-first, strict TypeScript.

```
apps/cli                    # the TriStack CLI (tristack / create-tristack)
apps/web                    # Next.js docs/site (tristack.space), Fumadocs docs
packages/template-generator # template engine (.hbs) used by the CLI
packages/types              # shared zod schemas + per-language constants
packages/tristack-py        # PyPI distribution of the CLI
```

Workspace deps are shared via the root `package.json` `catalog` (better-result, handlebars, zod, tsdown, etc.).

## 2. Package responsibilities

### 2.1 `packages/types`

- Zod schemas for a `ProjectConfig`, a `tristack.jsonc` config-file schema, and language-specific option catalogs.
- Per-language constants: frameworks, ORMs, migrations, packages managers, addons, frontends (`constants.ts`).
- Single source of truth for the option space shared by CLI, template generator, and web.

### 2.2 `packages/template-generator`

- `templates/<language>/…`: Handlebars template tree, layered as `base` → `core` → `framework/<fw>` → `orm/<orm>` → `migrations/<mig>` → dimensions → `addons`.
- `src/templates.generated.ts`: precompiled template bundle re-generated by `bun run generate-templates` after any template change (build runs it automatically via `prebuild`).
- Template handlers (`template-handlers/{base,python,go,rust}.ts`) resolve per-language copy order and helpers.
- Core helpers from `template-processor.ts` (`eq`, `ne`, `and`, `or`, `includes`) support conditional output (e.g. ORM-specific blocks).
- Virtual filesystem (`core/virtual-fs.ts`) + `fs-writer.ts`: generate in memory, then write to disk.
- Procedural `readme-generator.ts`: builds ORM/framework-aware README setup steps (auto-create schemas, Alembic, Django migrate, per-manager run commands).

### 2.3 `apps/cli`

Entry `src/cli.ts` → `src/index.ts` (`createTristackCli`). Key modules:

- `prompts/`: interactive prompt flow per dimension (framework, orm, migrations, database, package manager, addons, frontend, git, install, project-name).
- `validation.ts`: `validateResolvedConfigCompatibility` — cross-dimension compatibility rules; typed `ValidationError` results.
- `helpers/core/`: `create-project.ts` (scaffold + post steps), `command-handlers.ts`, `git.ts`, `install-dependencies.ts`.
- `utils/`: `errors.ts` (`CLIError`, `ProjectCreationError`, `UserCancelledError`), `project-name-validation.ts`, `terminal-output.ts`, external-command wrappers, better-result usage.
- `virtual.ts`: programmatic/virtual generation entry (used by tests and possibly by agents/MCP).
- CLI runner mapping: Python → `uvx tristack`; Go/Rust → plain `tristack` (curl/PowerShell installers). No npm/npx channel.

### 2.4 `apps/web`

Next.js app (Fumadocs). Highlights:

- Home single-pane init rail with a centered text wordmark and [stack builder](https://tristack.space/new).
- Stack Builder compatibility engine (`new/_components/utils.ts`) mirrors CLI validation; parity test `apps/web/test/stack-builder-compatibility.test.ts`.
- Docs content in `apps/web/content/docs`.
- `fumadocs-ui` is aliased to `@fumadocs/base-ui`.

## 3. Data flow

```
option selection (CLI prompts / flags / create-json / Stack Builder URL)
        │
        ▼
ProjectConfig (validated by packages/types zod + CLI validation)
        │
        ▼
template-generator handlers ──► VirtualFS (in-memory) ──► fs-writer (disk)
        │                        │
        │                        └── procedural README (ORM/framework-aware)
        ▼
post-scaffold: install deps, git init, start hint
        │
        ▼
tristack.jsonc (reproducible command)
```

## 4. Testing tiers

See `docs/CONTEXT.md` and `docs/adr/0001-use-tiered-matrix-testing-for-cli-stack-coverage.md`.

- **Default Suite**: fast unit/integration/regression tests run during development (`bun test` in `apps/cli`, `bun test` in `apps/web`).
- **Matrix Smoke**: representative slice in regular CI.
- **Full Matrix Job**: sharded long-running matrix over the normalized Core Stack matrix (`Create Path`).
